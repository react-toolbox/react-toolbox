# Material Design 1 audit

Audit date: 13 October 2026. Target: Google's archived [Material Design 1 guidelines](https://m1.material.io/), applied to React Toolbox's existing component families after the React 19 migration.

This is an implementation audit and correction record, not a certification of complete Material or accessibility compliance. It separates verified M1 corrections from modernization work and deliberate compatibility choices. Material 3 styling, Expressive variants, and additional component families are outside this pass.

The 15 October 2026 release-readiness pass includes explicitly approved accessibility
departures from original picker defaults: brighter small inactive header text,
Grey 700 clock numerals, and larger year/AM/PM pointer targets with unchanged text
positions. Their measured contrast, target sizes, and W3C sources are recorded in
[the accessibility guide](accessibility.md). A separate
`packages/react-toolbox/tests/accessibility-style-corrections.json` ledger applies
after the M1 ledger and validates each previous value; the archived fixtures are
unchanged. Reduced motion is an additional OS preference, while normal M1 motion
remains the default.

## Evidence and scope

The review used M1's component, layout, color, motion, and accessibility guidance, the original component source, and browser measurements. Existing CSS and the independent React 16 reference remain archived under `packages/react-toolbox/tests/fixtures`; they were not rewritten to approve the new appearance. Intentional declaration changes are recorded separately in `packages/react-toolbox/tests/fixtures/m1-style-corrections.json`. Ordinary migration parity and deliberate specification corrections therefore have different evidence.

M1 uses dp/sp measurements. The library's default `--unit: 10px` maps its existing token formulas to those measurements; consumers can still change the scale. Browser tests check the resulting CSS geometry. Exact shadow implementation was also checked against Google's historical [Material Components Web elevation variables](https://github.com/material-components/material-components-web/blob/v0.35.0/packages/mdc-elevation/_variables.scss), as an implementation reference rather than a replacement design specification.

Keyboard and semantic fixes implement M1's requirement that interactions be accessible beyond a mouse or touch gesture. A newly added focus outline is a practical web implementation choice; its exact CSS is not presented as an M1 illustration measurement. [Accessibility guidance](https://m1.material.io/usability/accessibility.html).

The icon alignment follow-up corrects two inherited layout bugs: the generic button span selector overrode the icon button's line height and vertical alignment, while avatars positioned child icons on a text baseline. The generic selector now yields to variant styles, and avatars apply their existing centered line box to child icons as well as icons supplied through props. `packages/react-toolbox/tests/browser/icon-alignment.spec.js` measures actual glyph line boxes with the Material Icons font loaded, covering app-bar actions, circular buttons, menu triggers, and both avatar icon APIs at desktop, phone portrait, and phone landscape sizes.

## Compatibility decisions

- Continuous sliders now follow the M1 state illustration: 12px at rest, 14px on hover, and 18px when pressed, with the existing larger interaction container. The hollow minimum rail gap follows the pressed thumb size.
- Original primary/accent branding, public component props, theme slots, and value-first callbacks remain the default contract. The audit does not recolor every selection control to a different accent or replace the public API with another component library.
- Existing motion curves and keyframes remain except where a documented correction is explicit. Calendar month transitions remain 350ms, clock view transitions 500ms, and existing ripple timings are retained; ripple sizing now accounts for the taller dimension of a target. Tooltip timing changes are listed above. M1's timing guidance is contextual, so preserving an existing duration is not a claim that all transitions must use one universal value. [Duration and easing](https://m1.material.io/motion/duration-easing.html).
- Runtime modernization uses typed function components and hooks, with DOM refs or explicit typed imperative handles. Component injection factories, styling wrappers, and runtime PropTypes are removed. Generated IDs and ARIA attributes change markup where necessary. Native disabled behavior and picker activation corrections are intentional behavioral differences.
- CSS custom properties and theme slots remain configurable. Scoped overrides only recompute dependent tokens and follow portaled content. The clock face has its own background token; a divider correction should not recolor a decorative surface accidentally.

## Validation and limits

Focused tests live in `packages/react-toolbox/tests/m1-*.test.jsx` and `packages/react-toolbox/tests/browser/m1-*.spec.js`. They complement the existing runtime, hydration, type, style, and original-runtime comparisons. Checks include real Chromium/WebKit geometry, control state ink, actual button hit areas, modal interactions, slider press/release, and progress animation samples. Browser fixtures that load CSS directly isolate styling; gallery tests exercise the React output and integration. Reproduce with `pnpm check`, `pnpm docs:build`, and `pnpm test:browser`; select WebKit with `TOOLBOX_BROWSER=webkit`.

Coverage is bounded. Passing these tests does not establish every font rasterizer, browser, screen reader, touch device, theme combination, or application flow as conformant. In particular:

- No automatic dark-theme palette, landscape picker variant, expanded contact-chip detail view, or automatic locale-based 12/24-hour detection was added. Existing props and explicit theme overrides remain available.
- General `--color-text` and secondary palette aliases remain for compatibility. Opaque legacy text greys do not reproduce alpha compositing on every colored surface; the specifically corrected state tokens use alpha ink. [M1 color guidance](https://m1.material.io/style/color.html).
- Dropdown `required` is exposed semantically, but the readonly display input does not provide native browser required-field validation. Applications must validate the selected value.
- Applications supply meaningful labels, modal names, actions, localized error wording/icons, and layout spacing. The library does not prepend an English error prefix, allocate every surrounding touch target, coordinate consecutive snackbars/FAB movement, or decide when an overlong menu should become a dialog.
- Optional platform/density variants and a full assistive-technology, RTL, contrast, and reduced-motion audit remain separate work. Additional variants should be evaluated against their own M1 evidence rather than inferred from Material 3 or from the legacy implementation alone.

## Documentation follow-up

The documentation shell and all 29 documented families were reviewed against the linked M1 sections. This pass covers documentation composition and usage, building on the implementation audit above.

- **Navigation:** replaced compact custom links with Toolbox List, ListItem, ListSubHeader, and ListDivider. Rows and subheaders are 48px, labels are 14px medium, horizontal keylines are 16px on phones and 24px on larger screens, and groups have 8px divider spacing. Links occupy the whole row, retain native keyboard/browser behavior, show selection and focus, and receive contained ripple feedback. Temporary mobile navigation closes after an ordinary route change and preserves focus restoration. The component search was removed. [Navigation drawer](https://m1.material.io/patterns/navigation-drawer.html), [Subheaders](https://m1.material.io/components/subheaders.html).
- **Foundations:** the docs scope primary/secondary text to 87%/54% black, retain the indigo/pink palette and 12% divider token, use a white preview surface and Grey 50 code surface, and use the 34px/45px regular display scale for article headings. The theming guide now explains alpha ink, the 8px layout grid, 4px subgrid, and touch areas. These scoped text changes do not silently recolor the original gallery. [Color](https://m1.material.io/style/color.html), [Typography](https://m1.material.io/style/typography.html), [Metrics and keylines](https://m1.material.io/layout/metrics-keylines.html).
- **Documentation controls:** preview/code tabs use 48px height, 72px minimum labels on small screens, and 160px minimum labels on larger screens. Clickable catalog cards use Toolbox ripple feedback inside the Card surface. The reset icon uses Toolbox Tooltip. Numeric values in the spacing table are right-aligned. [Tabs](https://m1.material.io/components/tabs.html), [Cards](https://m1.material.io/components/cards.html), [Tooltips](https://m1.material.io/components/tooltips.html), [Data tables](https://m1.material.io/components/data-tables.html).
- **Examples:** checkbox choices now form an independent option set; the dialog offers Cancel and Save with observable save behavior; the snackbar offers a working Undo instead of Dismiss; landing snackbars simply expire. Dialog/drawer/overlay/snackbar triggers and the tooltip use Toolbox Button. The List example uses keyboard-accessible full-row buttons and keeps informational status outside the action list. Copyable source and installation commands include all composed dependencies. [Selection controls](https://m1.material.io/components/selection-controls.html), [Dialogs](https://m1.material.io/components/dialogs.html), [Snackbars](https://m1.material.io/components/snackbars-toasts.html), [Lists](https://m1.material.io/components/lists.html).
- **Usage documentation:** every family has a Material guidelines section and an explicit M1 source link, separate from its React API notes. Composition helpers such as Navigation and Overlay are described as helpers rather than additional M1 component patterns.

### Catalog coverage

No additional component family is needed for the current documentation flows: existing AppBar, List, Drawer, Tabs, Card, Button, Table, Tooltip, and feedback components cover them. This is not a claim of a complete M1 catalog. Distinct unimplemented families are [bottom navigation](https://m1.material.io/components/bottom-navigation.html), [bottom sheets](https://m1.material.io/components/bottom-sheets.html), [expansion panels](https://m1.material.io/components/expansion-panels.html), [grid lists](https://m1.material.io/components/grid-lists.html), and [steppers](https://m1.material.io/components/steppers.html). They should be added as fully specified components when the library expands to support those flows. FABs, dividers, and subheaders are already exported within the Button/List families; they do not require duplicate implementations. Android platform widgets are not a missing web component.

### Follow-up validation

The production docs build, docs typecheck, and targeted lint pass. Browser checks in Chromium and WebKit cover the full-row navigation hit area, contained ripple, keyboard focus/activation, mobile drawer dismissal/focus restoration, clipboard feedback, corrected example actions, public registry URLs, and every component preview/code page at 320px width. All 29 copyable examples also bundle from their advertised isolated registry dependencies and compile with strict TypeScript. The original gallery remains unchanged.

This remains a bounded review, not a pixel-by-pixel certification of every application composition or a complete assistive-technology audit. The implementation limits and compatibility choices above still apply.

## Documentation refinement and distribution cleanup

The follow-up removes the permanent grey selected-row fill. Current navigation uses the primary text color and `aria-current`, with visible keyboard focus and transient ripple feedback. This follows M1's written selection guidance: a persistent grey background is not required. The permanent desktop sidebar now reaches the left edge below the full-width app bar, with full-width dividers and consistent 24px text/header keylines. Its 256px width is four desktop 64px increments; phone navigation remains a temporary drawer with 16px insets. [Navigation drawer: selection, dividers, and permanent variants](https://m1.material.io/patterns/navigation-drawer.html).

Code samples use server-rendered syntax highlighting with dark M1 palette shades on Grey 50. M1 does not define a code syntax theme; assigning those colors to tokens is a documentation design choice. Token colors meet 4.5:1 contrast on the chosen surface, and copying returns the exact unformatted source. Keyboard users can focus and scroll the code area. [Color](https://m1.material.io/style/color.html), [Accessibility](https://m1.material.io/usability/accessibility.html).

Public copied entries now use `material/button`, `material/theme`, and the corresponding unprefixed family filenames under the consumer's UI alias. This keeps Material components separate from existing shadcn components. File naming is a distribution decision, not a Material requirement. Existing prefixed imports need migration; the installer does not remove old files automatically. [shadcn target placeholders](https://ui.shadcn.com/docs/registry/registry-item-json#target).

Link and Navigation were retired from the public docs, registry items, and copied TypeScript exports. Native/router links inside semantic navigation or List rows cover these roles without a second routing wrapper. Their old docs URLs redirect to the installation guide's routing section. The public catalog has 27 families; the private workspace retains the old implementations only for historical gallery comparisons. This does not remove an M1 interaction pattern. Existing component geometry, motion, fonts, palette, and archived reference inputs remain unchanged.

Validation includes the production docs build, docs typecheck/lint, 27 isolated registry dependency closures, strict copied-source compilation, and a real shadcn CLI installation with a custom UI alias into a clean Next.js production app. Browser coverage checks both desktop and mobile layouts, selected-row geometry/ink, code colors and copying, retired routes, registry payloads, and all 27 preview/code pages. Source registry details and migration instructions are in [source-registry.md](source-registry.md).
