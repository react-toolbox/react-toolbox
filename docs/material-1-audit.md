# Material Design 1 audit

Audit date: 13 October 2026. Target: Google's archived [Material Design 1 guidelines](https://m1.material.io/), applied to React Toolbox's existing component families after the React 19 migration.

This is an implementation audit and correction record, not a certification of complete Material or accessibility compliance. It separates verified M1 corrections from modernization work and deliberate compatibility choices. Material 3 styling, Expressive variants, and additional component families are outside this pass.

## Evidence and scope

The review used M1's component, layout, color, motion, and accessibility guidance, the original component source, and browser measurements. Existing CSS and the independent React 16 reference remain archived under `tests/fixtures`; they were not rewritten to approve the new appearance. Intentional declaration changes are recorded separately in `tests/fixtures/m1-style-corrections.json`. Ordinary migration parity and deliberate specification corrections therefore have different evidence.

M1 uses dp/sp measurements. The library's default `--unit: 10px` maps its existing token formulas to those measurements; consumers can still change the scale. Browser tests check the resulting CSS geometry. Exact shadow implementation was also checked against Google's historical [Material Components Web elevation variables](https://github.com/material-components/material-components-web/blob/v0.35.0/packages/mdc-elevation/_variables.scss), as an implementation reference rather than a replacement design specification.

## Intentional corrections

| Family | Corrections and evidence |
| --- | --- |
| Buttons, FABs, and icons | Corrected button minimum width and horizontal padding to 88/16px, focus wash to 12%, pressed elevations, and disabled inverse ink. Preserved 36px visible buttons while providing 48px hit targets. Corrected ordinary icon-button targets and mini-FAB glyph sizing; the compact FAB breakpoint uses 460px. Native disabled links and file inputs now suppress activation correctly. Sources: [Buttons](https://m1.material.io/components/buttons.html), [FABs](https://m1.material.io/components/buttons-floating-action-button.html), [Icons](https://m1.material.io/style/icons.html), [Elevation](https://m1.material.io/material-design/elevation-shadows.html). |
| Text fields | Corrected idle label/bottom-rule ink to 54%/42% black, disabled text to 38%, and disabled rules to dotted. Counters are no longer always red. Error rules are 2px and remain red when focused. Fixed labels stay visible; icons occupy 24px with a 16px text gap. Labels, hints, errors, and counters now have stable associations; uncontrolled counters and multiline limits update correctly. Source: [Text fields: layout and states](https://m1.material.io/components/text-fields.html). |
| Dropdown and autocomplete | Added keyboard navigation/selection, focus indication, and combobox/listbox semantics while retaining the existing callbacks. Disabled options are skipped; dropdown forms submit option values. Autocomplete now selects the actual clicked suggestion, handles an empty query, escapes literal search characters, and does not select an undefined item. Arrow ink is independent of the underline: 54% at rest, 87% focused, 38% disabled. Sources: [Text fields](https://m1.material.io/components/text-fields.html), [Icons](https://m1.material.io/style/icons.html), [Accessibility](https://m1.material.io/usability/accessibility.html). |
| Checkbox, radio, and switch | Corrected unchecked checkbox/radio ink to 54% black and switch off-track ink to 38%. Added a visible checkbox keyboard-focus indicator. Switches are natively disabled when requested; radio children share the supplied or generated group name. Existing checkmark/ripple/thumb motion and control geometry remain. Source: [Selection controls](https://m1.material.io/components/selection-controls.html). |
| Chips | Plain labels now use 13px and 87% black; contact labels retain 14px. Delete-icon ink is 54%. Delete/Backspace and the accessible delete control remove chips without also activating their primary action. Disabled chips suppress activation/deletion. Height remains 32px. Source: [Chips](https://m1.material.io/components/chips.html). |
| Date and time pickers | Added current-day emphasis, month swipes, scoped calendar keyboard navigation, and keyboard access to the year/day and hour/minute controls. Date constraints compare calendar days rather than timestamps; disabled dates cannot be confirmed. AM/PM selection no longer changes the calendar date or toggles when the already-selected period is pressed. Date fields open on click/Enter/Space, so restoring focus after dismissal cannot reopen the dialog. The clock face retains its historical grey independently of divider changes. Source: [Pickers](https://m1.material.io/components/pickers.html). |
| Sliders, progress, and ink feedback | Corrected inactive/focused slider rail contrast and disconnected disabled-thumb treatment. Slider keyboard handling stays within its control; numeric editing, fractional steps, bounds, stop placement, and the minimum-thumb coordinate origin are covered. Determinate progress clamps its announced value; indeterminate progress does not announce a fabricated percentage. Zero circular progress no longer paints a round-cap dot, and disabled circular ink remains disabled during animation. Ripple feedback ignores secondary mouse buttons and ends on touch cancellation. Sources: [Sliders](https://m1.material.io/components/sliders.html), [Progress and activity](https://m1.material.io/components/progress-activity.html), [Accessibility](https://m1.material.io/usability/accessibility.html). |
| Dialogs and temporary drawers | Added meaningful modal semantics, focus containment/restoration, inactive-surface handling, and topmost-only Escape dismissal. Corrected dialog viewport margins, scrolling body/fixed action layout, action sizing, and title spacing. Drawer elevation and maximum width now follow the reviewed guidance. Picker selectors were updated to retain their compact layout after removing invalid dialog roles. Sources: [Dialogs](https://m1.material.io/components/dialogs.html), [Navigation drawer](https://m1.material.io/patterns/navigation-drawer.html). |
| Menus and tabs | Menus support keyboard opening, arrows, Home/End, typeahead, activation, dismissal, and focus restoration. Long menus stay within the viewport, including after scrolling to their trigger; unmeasured right-origin menus no longer cause phone page overflow. Static menu outlines track their actual content bounds, including font loading and margins. Tabs have roving focus, relationships to panels, disabled/hidden fallback handling, and RTL keyboard direction. Corrected icon-only/icon-with-text heights and inverse inactive-label opacity. Sources: [Menus](https://m1.material.io/components/menus.html), [Tabs](https://m1.material.io/components/tabs.html). |
| Tooltips and snackbars | Tooltips now support focus, descriptions, Escape, and touch long-press/release behavior. Corrected desktop/mobile text sizing, height, spacing, and the specified entrance/exit timing. Snackbars have a live status role and pause dismissal while interaction or page visibility requires it. Corrected surface color, desktop bounds, and mobile multiline height. Sources: [Tooltips](https://m1.material.io/components/tooltips.html), [Snackbars and toasts](https://m1.material.io/components/snackbars-toasts.html). |
| Cards, lists, tables, and dividers | Corrected card headline/subtitle metrics, avatar-header height, responsive content spacing, three-line list height, and action alignment. Corrected table gutters and sort-hover ink. Dividers use 12% ink rather than an opaque grey approximation. Sources: [Cards](https://m1.material.io/components/cards.html), [Lists](https://m1.material.io/components/lists.html), [Data tables](https://m1.material.io/components/data-tables.html), [Dividers](https://m1.material.io/components/dividers.html). |
| App bar and layout | Corrected mobile portrait/landscape and tablet toolbar heights, horizontal insets, and title positions, including clipped layouts. Avatar, FontIcon, Link, and Navigation helpers were reviewed without replacing their existing design with unrelated variants. Sources: [Structure](https://m1.material.io/layout/structure.html), [Responsive UI](https://m1.material.io/layout/responsive-ui.html). |

Keyboard and semantic fixes implement M1's requirement that interactions be accessible beyond a mouse or touch gesture. A newly added focus outline is a practical web implementation choice; its exact CSS is not presented as an M1 illustration measurement. [Accessibility guidance](https://m1.material.io/usability/accessibility.html).

The icon alignment follow-up corrects two inherited layout bugs: the generic button span selector overrode the icon button's line height and vertical alignment, while avatars positioned child icons on a text baseline. The generic selector now yields to variant styles, and avatars apply their existing centered line box to child icons as well as icons supplied through props. `tests/browser/icon-alignment.spec.js` measures actual glyph line boxes with the Material Icons font loaded, covering app-bar actions, circular buttons, menu triggers, and both avatar icon APIs at desktop, phone portrait, and phone landscape sizes.

## Compatibility decisions

- Continuous sliders now follow the M1 state illustration: 12px at rest, 14px on hover, and 18px when pressed, with the existing larger interaction container. The hollow minimum rail gap follows the pressed thumb size.
- Original primary/accent branding, public component props, theme slots, and value-first callbacks remain the default contract. The audit does not recolor every selection control to a different accent or replace the public API with another component library.
- Existing motion curves and keyframes remain except where a documented correction is explicit. Calendar month transitions remain 350ms, clock view transitions 500ms, and existing ripple timings are retained; ripple sizing now accounts for the taller dimension of a target. Tooltip timing changes are listed above. M1's timing guidance is contextual, so preserving an existing duration is not a claim that all transitions must use one universal value. [Duration and easing](https://m1.material.io/motion/duration-easing.html).
- Runtime modernization uses typed function components and hooks, with DOM refs or explicit typed imperative handles. Component injection factories, styling wrappers, and runtime PropTypes are removed. Generated IDs and ARIA attributes change markup where necessary. Native disabled behavior and picker activation corrections are intentional behavioral differences.
- CSS custom properties and theme slots remain configurable. Scoped overrides only recompute dependent tokens and follow portaled content. The clock face has its own background token; a divider correction should not recolor a decorative surface accidentally.

## Validation and limits

Focused tests live in `tests/m1-*.test.jsx` and `tests/browser/m1-*.spec.js`. They complement the existing runtime, hydration, type, style, and original-runtime comparisons. Checks include real Chromium/WebKit geometry, control state ink, actual button hit areas, modal interactions, slider press/release, and progress animation samples. Browser fixtures that load CSS directly isolate styling; gallery tests exercise the React output and integration. Reproduce with `npm run check`, `npm run example:build`, and `npm run test:browser`; select WebKit with `TOOLBOX_BROWSER=webkit`.

Coverage is bounded. Passing these tests does not establish every font rasterizer, browser, screen reader, touch device, theme combination, or application flow as conformant. In particular:

- No automatic dark-theme palette, landscape picker variant, expanded contact-chip detail view, or automatic locale-based 12/24-hour detection was added. Existing props and explicit theme overrides remain available.
- General `--color-text` and secondary palette aliases remain for compatibility. Opaque legacy text greys do not reproduce alpha compositing on every colored surface; the specifically corrected state tokens use alpha ink. [M1 color guidance](https://m1.material.io/style/color.html).
- Dropdown `required` is exposed semantically, but the readonly display input does not provide native browser required-field validation. Applications must validate the selected value.
- Applications supply meaningful labels, modal names, actions, localized error wording/icons, and layout spacing. The library does not prepend an English error prefix, allocate every surrounding touch target, coordinate consecutive snackbars/FAB movement, or decide when an overlong menu should become a dialog.
- Optional platform/density variants and a full assistive-technology, RTL, contrast, and reduced-motion audit remain separate work. Additional variants should be evaluated against their own M1 evidence rather than inferred from Material 3 or from the legacy implementation alone.
